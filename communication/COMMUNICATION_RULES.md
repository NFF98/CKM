# CKM｜溝通與文件語言原則

**狀態：正式生效**  
**預設語言：繁體中文（zh-TW）**  
**適用對象：使用者、AI 助理、Cursor/開發代理與任何 Repository 協作者**

## 原則 01｜輸入語言不限，所有溝通使用繁體中文

使用者可以輸入英文、繁體中文或混合語言；**所有回覆及後續說明仍一律使用繁體中文**。不應要求使用者改用中文輸入。

## 原則 02｜所有 CKM 工作文件使用繁體中文

以下內容須使用繁體中文撰寫及維護：

- Business／Functional／System Design 的新增或改版說明
- Build Backlog、Sprint 規劃、功能需求與驗收標準
- GitHub Issue、Pull Request、Commit 訊息、Code Review
- Test 測試計畫與結果、Debug 問題與原因分析
- Deploy 部署、回滾與版本發布紀錄
- Chat、進度報告、決策紀錄、交接說明

**例外**：技術專有名詞、程式識別字、套件／產品名稱、命令、路徑、第三方資料與逐字引用來源可保留英文。說明文字仍須繁體中文。

## 原則 03｜不得任意修改使用者提供的原始文件

使用者上傳至 `design/doc/` 的原始規格與商業設計，除非明確要求修改，否則完整保留。**語言原則對新建立與修改後的溝通文件生效，不代表可以破壞來源資料。**

## 原則 04｜如何執行

1. 開始工作前，先讀根目錄 [AGENTS.md](../AGENTS.md)。
2. 更新文件前，確認使用繁體中文標題、表格、說明及驗收條件。
3. 建立 GitHub Issue／PR／Commit 時使用繁體中文描述。
4. 若因引用英文 API 或原文範例而出現英文，請以繁體中文補足說明。
5. 若發現自己新增英文工作文件，應修正，不再用英文建立替代版。

**此規則在 CKM 的設計、建置、測試、除錯、部署與溝通工作區均有效。**
